# 六人二开安排：减重复建设，不减核心业务

## 先统一这六件事

1. 只做桌面 Web，不做手机适配、App、小程序。
2. 保留个人条件＋意图推荐、完整签证资料、世界各区域主要国家覆盖。
3. 所有人使用本 base。框架、数据库脚本、接口、基础页面、规则比较和测试已有实现，不再分别重建。
4. 数据收集和验证仍然是真实工作量；不能把 250 个目录条目或 9 条虚构演示当成政策已完成。
5. 一个事实只有一个维护位置；前端不另存费用和材料，地图不另建国家表，B 不再从头开发 API。
6. 所有影响交付的沟通写入对应双边协议的记录栏；普通讨论不额外造文档。双方确认才生效，当前协议都是待签认底稿。

## 优化后的职责

| 人员 | 核心责任 | Base 已替他做好 | 仍需交付 | 明确不负责 |
|---|---|---|---|---|
| A | 收集资料、首次建库、字典维护 | 表结构、模板、建库与导入工具 | 按国家批次的完整资料、逐字段来源、缺项说明 | 不独自确认事实、不做页面、不重写数据库接口 |
| B | 交叉验证、规则整理、手动更新 | API 框架、校验器、备份与更新工具 | 复核记录、可发布批次、更新记录、API 资料准确性确认 | 不同时承担全套后端开发，不做爬虫 |
| C | 后端框架、接口运行、服务配置 | Fastify、MySQL 适配、推荐引擎 | 接口增量、部署说明、地图安全服务对接 | 不写地图交互，不替 A/B 判政策事实 |
| D | 前后端接线、跨模块测试、合并 | 页面总体状态与基础调用、测试样例 | 可重复验收步骤、合并记录、发布版本 | 不替每个成员修完全部问题；退回原作者修复 |
| E | 搜索、推荐交互、完整资料阅读体验 | 搜索框、字典排序、筛选、推荐表单与详情 | 同义词/搜索体验改进、输入与错误提示、推荐解释 | 不另造推荐算法或复制数据库 |
| F | 高德地图与页面内地图交互 | 地图组件、国家点击回调、无 Key 提示 | 真实高德配置验证、选择联动、加载失败体验 | 不做签证资料爬取、路线导航、3D 地球或移动端 |

原先“B 写 API、C 再整合一套 API”容易重复。现在 **C 是 API 实现唯一主责，B 负责数据含义与结果复核**；二人通过 B-C 协议约定字段和样例。D 只负责接好、查明问题归属和验收，不成为所有模块的补漏人。

## 开工先后（以通过检查为准，不承诺几天收齐世界政策）

| 阶段 | A / B | C | D | E / F | 放行条件 |
|---|---|---|---|---|---|
| 0：同一底座 | A 建测试库，B 熟悉模板 | 跑通 demo 与 MySQL 两种模式 | 确认每人可启动，确定首个主干基线 | E 跑搜索推荐，F 确认 Key 申请条件 | 六人都能展示页面，双边协议认领 |
| 1：一条真实链路 | A 采 1 条完整真实路线；B 逐项复核 | 导入后 API 返回同一版本 | 从查找、选择、详情到推荐逐项验收 | 用同一条资料验证界面与地图 | 不靠 demo 也能完成一次端到端演示 |
| 2：并行增量 | A 每批 3–5 个目的地；B 滚动复核上一批 | 修正真实数据暴露出的字段边界 | 每合并一批做回归，不等最后一天 | E 只改搜索/推荐体验，F 只改地图 | 数据批次有来源，代码批次有测试 |
| 3：扩展覆盖 | 依据覆盖账本持续补齐全部目标 | 必要时再做分页、性能或规则扩展 | 审核主要国家/用途缺口与发布说明 | 不用堆动画代替功能验收 | 覆盖证据与已知缺口清楚可查 |

## 如何真正减负

- 每人首次只交一个小改动，证明能在同一 base 工作；不要求每人单独起项目、写接口、建表。
- A 先做模板复用和批次组织；B 复核上一批，二人不互相等到“全部收完”。
- 每次交付只写一个短 PR，附测试结果与对应协议版本；不要求重复写长周报。
- 初期不做登录后台：B 用脚本手动更新，省去后台 UI、权限系统与自动任务维护。
- 不做多级微服务、消息队列、自动爬虫、实时汇率、机器学习模型；已有确定规则实现核心匹配。
- E/F 若先完成工程任务，可按 A 提供模板整理资料草稿；A 仍合并采集批次，B 仍做最终交叉核验，避免所有人写数据库。

## 不能含糊的边界

“主流国家”需由负责人确认可检查清单；现有 91 个仅是首批候选，不能以此删掉其他主要目的地。所有 250 个目录保留后续任务。每个国家还需写清申请人范围、渠道、用途，而不是只存一条旅游签证就声称该国完成。

这份 base 减少的是工程重复；全球政策的准确收集、来源复核、复杂例外处理仍需持续投入。某个国家某用途没有独立签证时记录权威依据，不编造一条路线凑七类。
