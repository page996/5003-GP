# 同一仓库协作与统一验收

## 每人只维护一份主干基线

远程仓库：<https://github.com/page996/VisaAtlas-workspace>。当前 base 在本地准备，首次 commit/push 由负责人确认后执行；这里没有擅自推送。

建议默认分支 `main`，每人从最新主干建立一个小任务分支：`data/a-...`、`data/b-...`、`backend/c-...`、`integration/d-...`、`search/e-...`、`map/f-...`。这是协作约定，不代表已经创建这些分支。

```text
git fetch origin
git switch main
git pull --ff-only
git switch -c <角色/具体任务>
完成一个小改动和对应检查
git add <本次文件>
git commit -m "简明说明本次修改"
git push -u origin <角色/具体任务>
在 GitHub 创建 PR，附对应协议和验收结果
```

主干不直接推送、不 force push、不交互修改别人分支。D 统一合并；D 自己的改动由 C 或相关模块负责人审。仓库所有者设置分支保护：至少一位非作者批准、必需 CI、禁止强推；这些权限尚需在 GitHub 实际配置。

## 不要把“整合”变成最后一个人的大作业

- 原作者负责可运行的增量、类型和相应测试；不能只交一段复制粘贴的代码让 D 重建。
- 每个 PR 只改自己的文件范围。跨边界先在双边协议留下字段/文件/交付时间/验收变化，不口头改接口。
- `shared/contracts.ts`、`database/schema.sql`、`client/App.tsx`、依赖和锁文件都是重点交接文件；由 C、A/C、D、C 分别协调。
- 解决冲突时双方看同一份 diff，不覆盖对方整文件；主干更新后再验证。
- 数据 PR 写真实来源和缺项，不混入密钥或个人申请资料。`.env`、`local/`、数据库目录、依赖目录、构建输出不入库。
- 发布使用小版本说明；合并后由负责人按需要打标签，所有人从同一版本继续。不要靠聊天里传 ZIP 互相覆盖源码。

## 每个 PR 最少填写

改了什么、对应角色/协议、怎么启动/重现、运行哪些检查、截图或响应样例、是否改数据或契约、已知不足。提供模板 `.github/pull_request_template.md`；不要求长篇汇报。

## 自动检查

```powershell
npm ci
npm test
npm run build
npm run data:validate -- data/policies.json
```

涉及某个数据批次时，再校验该批次。提供的 GitHub Actions 在 PR/主干推送时运行上述检查；还未推到远程，因此未实际触发远程 CI。MySQL 不在这条 CI 中，不声称线上自动测了数据库。

## 专用 MySQL 集成测试

**有写库、替换资料与回退操作。只能用可丢弃的本机专用库，不得用正式资料库。** 测试有三项保护：`RUN_MYSQL_TESTS=1`、数据库名以 `_test` 结尾、`DB_HOST=127.0.0.1`。

按 README 建立新的 `visa_atlas_test` 及它的管理员/只读用户，为它设置 `DB_NAME` 和本地口令，运行 `npm run db:init`。不要复用正式库管理员的口令到公开命令记录。

```powershell
$env:DB_HOST='127.0.0.1'
$env:DB_NAME='visa_atlas_test'
$env:RUN_MYSQL_TESTS='1'
npm run test:mysql
Remove-Item Env:RUN_MYSQL_TESTS
```

运行前还须通过本地 `.env` 或当前进程变量填写该测试库的 `DB_PORT/DB_ADMIN_USER/DB_ADMIN_PASSWORD/DB_USER/DB_PASSWORD`。结束后恢复你的工作环境；不要只改了库名却仍用错误账户或端口。

## D 的桌面统一验收清单

| 检查 | 预期 |
|---|---|
| 初次启动、刷新 | 同一目录、版本、模式；demo 明确可见 |
| 英文/中文/部分名称/用途搜索 | 对应结果，清空恢复；无结果不误判无签证 |
| 列表与地图选中 | 同一国家，详情保持正确；键盘可用列表等效选择 |
| 完整路线 | 所有材料、费用、时间口径、有效与停留、规则和来源可读 |
| null、0、来源冲突 | 未知不当免费或无需材料；冲突不当可靠条件 |
| 个人条件＋意图 | 可提交并解释匹配/不符/未知，分数不是获签率 |
| 缺规则/过期/演示/跨币种 | 保留需核实结论，不虚报合格 |
| API 400/404/503 | 有准确状态、可理解的错误和重试；无密码泄露 |
| MySQL 更新/失败/回退 | 先计划再应用；失败无半更新；只读账户不能写 |
| 高德 | 真实服务另行测试；离线坐标示意不是通过证明 |
| 1280 与 1600 桌面宽度 | 内容可读、无阻断操作；不做手机验收 |
| 数据覆盖 | 目录、候选、真实路线、核验情况分开说明 |

不通过时由 D 指派原作者修复；D 记录复现条件、路线号、截图或响应和复验结果。不得仅为通过验收删未知字段、减少国家或取消推荐。
