# 全球覆盖推进：不以目录条数替代真实政策

## 当前基线

- 地理目录：250 个国家与地区。覆盖任务：每个目录项七类用途。
- 首批重点候选：91 个，来自显式可修改的清单，不是全球主流国家的官方定义。
- 真实路线：0；已核验真实路线：0。9 条 demo 永远不计入真实覆盖。

## 一次只移交一个可核验批次

1. D 与负责人先确认“目标国家、申请人范围、用途、渠道”验收账本；不隐含只服务某一种国籍。
2. A 对每批 3–5 个目的地做资料调查。先打通一个真实路线，而后逐步补齐其余用途及主要申请情形。
3. B 在上一批复核期间，A 开始下一批。发现无法可靠获取的事实保留 null，不猜补。
4. E/F 工程完成后可协助整理来源索引、初稿，但不得自签验证；B 保持统一核验。
5. 每批执行 `npm run data:coverage -- data/batches/<批次>.json`；这是该文件范围的结果，不代表整个数据库。全库报告需先导出，再对导出文件运行该命令。
6. 各国规则并非七种独立签证。某用途不适用、合并办理或无独立类型时，账本记录官方依据和复核人，不编造路线凑齐。

## 状态怎样解读

`NOT_COLLECTED` 无公开真实路线；`IN_PROGRESS` 有真实路线但未达到严格完整度；`PARTIAL` 部分用途有完整近期复核路线；`TARGET_TYPES_PRESENT` 目标用途都出现了至少一条此类路线。

现有完整度指标要求名称/适用范围、有效与停留说明、完整材料、已知费用及办理时间、完整规则和近期复核，属于保守的工程指标。官方明确未公布时长等情况可合法保留 null，界面和来源仍能展示，但不因此强行通过机器“完整”计数；由人工账本补充“已调查、官方未公布”的说明。

**即便 `TARGET_TYPES_PRESENT` 也不是该国所有签证政策已穷尽。** 覆盖不能只用一个百分比：同时汇报目的地清单、用途、申请人范围、渠道、资料完整度、来源可访问性和核验日期。
