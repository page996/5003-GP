# B｜资料核验、更新与数据接口口径职责书

## 你要完成什么

你是资料可信度负责人，不是第二个全栈后端。接口骨架、校验、备份、更新脚本已经提供；C 负责其代码，你负责确定返回的内容是否正确、完整且有依据。

1. 接收 A 的每批完整路线，逐项打开官方来源并与另一个权威/授权/成熟平台来源交叉核对，写下适用人群、差异和结论。
2. 保留所有材料、费用项目、时长口径；不能为了页面好看把明细合成“若干材料”或一个无条件价格。
3. 对冲突事实不猜答案：暂不公开路线或将对应事实置 null，并保留待核实说明。单一来源如实标记，不谎称双源核验。
4. 将明确个人条件整理为现有规则。不能完整表达的例外保留文字，规则标 PARTIAL，与 C 商定扩展。
5. 负责正式演示库手动更新、复核日期、备份和回退记录。无需爬虫、定时抓取、自动更新或管理员网页。

## 固定更新步骤

按 `docs/DATA.md` 执行：收集→复核→校验→生成计划→检查路线和库→确认应用→导出→通知 D 刷新验收。脚本会在写库前备份和检查版本；你仍需人工确认资料与目标库。

不得直接给前端 MySQL 账户，不提供网页 UPDATE 接口。不能只上传费用字段让脚本猜怎样合并；导入单位是完整路线。每批留更新版本、来源变化、操作者及本地备份位置，敏感路径/口令不公开。

## 交付物

| 内容 | 接收人 | 验收 |
|---|---|---|
| 每批逐项复核记录、可用来源/冲突结论、完整数据 | A/D | 人能按链接和定位重查；没有空值冒充已知 |
| 个人条件规则与至少一组匹配/不符/未知用例 | C/E | 推荐解释符合资料，不把未知判通过 |
| 来源更新及 `lastVerifiedAt/refreshDueAt` | C/D | API 和页面显示同一批内容与日期 |
| 应用、备份、必要时回退的记录 | D | 测试库演练可复现，无公开写接口 |

## 和谁沟通

A-B 约定字段含义和退回标准；B-C 约定数据/API/规则含义；B-D 约定发布门槛；B-E 约定未知、来源、推荐理由怎么说；B-F 只约定地图上的资料状态，不让有坐标被误画成已核验。

## 不用再做什么

不从零创建 Fastify，不重复写 CRUD，不做前端详情页，不负责高德配置，不独自收齐全部国家。必要的数据解释交给 C 实现、E 展示、D 验收。Base 能减少重复开发，不能代替你实际打开来源验证。
