# E｜搜索、推荐与资料展示职责书

## 你接手什么

让用户在桌面网页中找到目的地、读全资料、填写个人条件并理解推荐。Base 已有可运行搜索/推荐表单/详情，不要求重画整个网站或复制后端算法。

## 必须保留和完善的功能

1. 国家英文 A–Z 字典列表；中英文名、代码、别名和签证名称的宽松大小写/子串搜索。
2. 国家、区域、用途筛选，清空筛选和空结果说明；国家没有已收集资料不等于没有签证。
3. 个人条件（护照地、居住地、年龄、身份、护照余期、已有签证）＋出行意图（用途、地区、停留、申请费预算、处理时间、偏好）的输入。
4. 推荐必须调用统一后端，显示逐项通过/未知/不符及原因和资料来源；评分不是获签概率。
5. 完整展示材料、有效期、停留期、费用细项、办理口径、适用范围、核验时间和来源。不能为了短卡片删掉详情字段。
6. 处理等待、错误、重试、无数据及键盘操作。只验收桌面宽度，不承担手机布局。

## 文件与交付

主责 `client/features/search/`、`client/features/recommendation/`、`client/features/details/`。共用样式先和 F/D 划区；`client/App.tsx` 的总体联动请 D 接，不复制一套状态。

交付代码、用例、桌面截图及剩余交互问题。至少用 `japan`、中文名、用途筛选、无结果、null/0、两条已有签证代码、未填个人条件、不同币种与过期资料检查。

## 沟通与不做事项

E-F 约定整体配色、国家选中态和空态；C-E 约定 API 与错误；B-E 确认政策用语和推荐解释；D-E 接线与验收；A-E 仅确认收集字段是否完整展示。

不在页面硬编码政策数值，不做登录/个人档案储存，不训练推荐模型，不要求 A/B 缩略资料来迁就 UI。复杂条件无法判定时显示“需核实”，不要前端擅自判通过。
