# C｜后端框架与接口整合职责书

## 你接手什么

统一后端的运行方式、数据读取、推荐计算和地图需要的服务端配置。已有 `server/`、`scripts/` 与 API 契约，先跑通，之后只改真实需求暴露的缺口，不重搭另一套框架。

## 具体工作

1. 接入 A 建立、B 发布的 MySQL 数据，保持运行账户只读、管理员脚本另用账户。确认 demo 与 mysql 不能悄悄混用。
2. 维护 `docs/API.md` 的接口；前端地图和搜索共享国家代码、路线对象及错误格式。
3. B 提出新规则、字段或口径时，先确认来源和含义，再扩展类型、校验、读写与测试；不是自行编写签证规则。
4. 维护计划预览、确认写入、事务、备份、过期计划拒绝。无需公开管理后台、实时任务和自动抓取。
5. 与 F 核对高德当前官方安全方案。前端 JS 地图由 F 加载，只有必要代理和秘密配置留在后端；不要为了“整合所有 API”重复代理每个地图操作。
6. 与 D 交付可重复启动的桌面 Web 服务。初版同源 API，不做手机设备适配。

## 文件与交付

主责 `server/`、`scripts/`，`shared/contracts.ts` 由你维护，但涉及显示/数据/接线变更需对应成员确认。依赖及锁文件变更同一 PR 提交，其他人勿各自替换依赖版本。

交付：环境模板无秘密、API 文档及样例、代码、相应测试、建库/运行/故障说明、高德服务端方案（若需要）及实际验证结果。

## 验收条件

- `npm test`、`npm run build` 通过；专用测试库的 MySQL 测试通过。
- 读库失败返回 503，不返回演示数据伪装正常；未知路线 404，非法参数 400。
- 更新后前端刷新可看到相同版本；运行账户执行 UPDATE 被拒绝。
- 未知、过期、冲突来源和复杂未表达规则不能产生无条件“符合”结论。
- 不把 Key 的安全密钥、管理员密码、个人画像写进页面构建产物或日志。

## 交接先后

A-C 确认表与字典 → B-C 确认政策和规则 → C-E/C-F 确认调用方式 → C-D 接线与服务验收。E/F 可以先用 demo 开发，不必等待全球资料；D 发现模块问题退回你，不要求 D 改写后端。
